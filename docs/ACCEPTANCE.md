# 0.4.0 验收记录

验收日期：2026-10-13（Asia/Singapore）。环境：Apple Silicon、macOS 27.2、Swift 6.4、Python 3.12.13、Docling 2.138.0。这里只记录本次实际检查范围，不代表任意文档都能无损识别。

## 0.4 Liquid Glass

- 使用 macOS 26+ SDK 构建，最低运行版本仍为 14.0。最终二进制核对 `LC_BUILD_VERSION`：`minos 14.0`、`sdk 27.0`。实测发现本机 Swift Build 引擎会错误写入 `sdk 14.0`，从而让系统启用旧外观；构建脚本改用 SwiftPM native driver，并在打包前检查实际 SDK 标记，低于 26 直接失败。
- 原生分栏、可折叠侧栏、工具栏、玻璃按钮及拖入提示完成适配。浅色/深色显示在隔离外观程序中检查；内容最小尺寸 900 × 600 与默认窗口均无底部裁切。修正了分栏理想高度导致设置入口和状态栏越界的问题。
- 自定义拖入提示的降低透明度分支在隔离程序中强制为真，确认浅色/深色实底、边框与文字；未更改用户全局辅助功能设置。原生控件的减少动态效果遵从系统实现，客户端未新增动画或轮询。
- Icon Composer 分层源由 `actool` 实际编译；默认、深色、染色图标经 Apple `ictool` 渲染检查。包中同时包含 `Assets.car` 和旧系统 `.icns`，图标 metadata 来自编译器生成的 plist。
- 真实 Finder 多选两份 PDF，以授权的 CGEvent 鼠标手势拖入空白详情区：自动处理并命中已有缓存，两份完整结果复用原保存目录，HTML 预览正常。随后拖到 Markdown 正文，队列仍为两份；单份重复文档拖入玻璃侧栏后，该记录置顶并选中，底栏确认新增 0 份。

## 0.2 批量与生命周期回归（历史基线）

- 1,000 文件目录在后台扫描；重复导入不增加条目，文件修改后可以再次加入。
- 100 HTML / 20 种内容的真实 Docling 批次：第一批命中 80 份，第二批命中 100 份；缓存全命中不初始化转换器。
- 文件内容、OCR、模型身份、引擎锁与工作代码变化均使旧缓存失效；缺结果或缺 manifest 时重建；失败及部分成功不进入缓存。
- 缓存容量和过期清理保留当前引用结果；另一转换进程被缓存锁拒绝，避免双份模型争抢资源。
- 实时 stdout 事件不等待管道填满；取消清理忽略 TERM 的后代，也覆盖父进程已退出的场景。
- 批量导出同名及大小写冲突自动编号；512 KiB 预览边界不截断实际导出。
- 真实 Docling 生成的 4 MiB JSON，经复用导出后来源文件名正确，中文、引号、64 位无符号哈希不丢失，正文逐字节一致且共享缓存未修改。
- 未知 JSON 结构不覆盖已有导出；512 MiB 大文件复制进行中取消，临时文件被清理、已有目标内容保留。
- 真实 uv 修复失败时，移除旧环境就绪标记；重新启动也不会误报可用。该回归使用隔离环境，不修改实际安装环境。
- 模型下载失败、验证失败、取消时不写假状态；成功状态包含确切引擎锁和 snapshot。实际离线加载验证及 PyPI 版本检查成功。

## 真实跨窗口鼠标拖拽（0.2.1）

用户授权使用 macOS CGEvent，实际从 Finder 多选测试文件及文件夹，按下鼠标、连续移动并在客户端释放；没有用文件选择器、URL 打开或直接调用队列方法代替。

首次复现出 0.2.0 的问题：空窗口可以接收，HTML 预览区则由 WebKit 吞掉拖放，底栏仍正常。0.2.1 增加专用 WKWebView 拖放处理，将本地文件 URL 转交原有导入队列，保留预览与导航限制。

修复后实际回归：

1. 将一个 HTML 和两个子文件夹同时拖到空窗口，读取三个 HTML 文件，队列为 3。
2. 转换完成并显示 HTML 预览后，将同一批再次拖到预览区，显示「已添加 0 份，跳过 3 份未改变的文件」，队列仍为 3。
3. 在 Finder 批次中加入 `追加.md`，将四项再次拖到预览区，显示新增 1 份、跳过 3 份，队列为 4；原有预览未被导航替换。
4. 转换追加文件，全部四份完成，三份复用缓存，批次结束释放模型。

最终窗口见 [drag-drop.png](drag-drop.png)。三组 NSPasteboard 自动检查将文件 URL 接收规则纳入 CI。后续交互优化扩大到整个内容区，加入常驻虚线提示和拖入时的整窗覆盖提示；真实鼠标在右侧内容区边缘悬停时的截图见 [drop-hover.png](drop-hover.png)。

## 自动队列和短时提示

新版原生窗口已实际验证自动转换，重新添加的记录移到顶部并选中，提示消退后恢复「已完成」。新增真实引擎回归已验证：导入即自动转换；不同文件的相同内容复用结果；重新添加相同文件时不新增行、移到顶部并选中；4 秒后复用提示消失，记录保持已完成。提示共用一个睡眠任务，到期后没有常驻轮询。

真实运行中停止后，队列进入暂停状态；此时新增文件保持等待，手动继续后转换；重试取消的文件会自动开始。右上角普通开始按钮已移除，仅运行时显示停止、暂停且有等待项时显示继续。

## 0.3 自动保存及大文档预览

- 每份文档自动保存三种完整格式到 `~/Docling_Mac/原文件名/`。同名不同源编号，重复结果复用目录；重新启动可识别用户在 Finder 改名后的目录；转换条件变化保留旧版本。
- 保存缺少格式时新建目录，保存中途失败不发布半份结果、不覆盖已有文件；显示保存错误，可单独重试保存。
- 保存队列串行，退出等待已完成或部分完成的结果保存；保存故障仍存在时会取消退出并保留结果，修复后重试再退出通过；清空队列保留永久结果。所有自动测试注入临时保存根目录，不向真实主目录写测试文档。
- 真实写入并读取 100 MiB 边界样本；刚好 100 MiB 的 HTML 完整加载，100 MiB + 1 字节 HTML 转有限 Markdown，Markdown 自身按 100 MiB 截断，磁盘结果不截断。
- 按当前模式读取一种格式；切换时取消旧任务并等待旧读取退出，再申请新预览内存。旧读取的分块取消检查通过；从大文档快速切到小文档，旧结果不会覆盖新选择。Markdown 使用只读原生 NSTextView 非连续布局。

在本机原生窗口实测现有 46 页及 77 页 PDF：HTML 结果约 5.1 MB / 7.6 MB，均显示完整排版，不再退化为含 base64 的有限文本；Markdown 原生视图切换成功。「打开结果」在 Finder 中显示对应源文件目录及完整 MD / HTML / JSON。用户文档和截图不提交到仓库。另以真实 CGEvent 从 Finder 将原 PDF 拖入新的 Markdown 原生文本区域，队列仍为两份，原记录移顶并选中，未吞掉拖放或创建重复目录。
