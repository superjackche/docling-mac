# 0.2.0 验收记录

验收日期：2026-10-13（Asia/Singapore）。环境：Apple Silicon、macOS 27.2、Swift 6.4、Python 3.12.13、Docling 2.138.0。这里只记录本次实际检查范围，不代表任意文档都能无损识别。

## 自动检查

`./scripts/test.sh` 覆盖 21 组 Swift 检查（16 组客户端、5 组导出）和 28 项 Python 测试，全部通过。最终构建后分段执行同一测试脚本中的命令，保留实际输出。

- 参数按原样传给子进程，中文、空格、shell 特殊字符不会被执行；保留非零退出码。
- 取消终止子进程；可执行文件缺失正确报错。
- 解析部分成功与不完整事件；40,000 字符警告不被界面日志上限截断。
- 队列输入校验、去重、重试与移除；导出拒绝覆盖输入及其符号链接。
- macOS Foundation 启动的 Python 进程正确进入事件协议。
- 实际 Docling 子进程取消后队列标记为已取消，运行状态释放；手动重试成功，并加载真实中英文预览。
- 中文 HTML 标题、段落、列表、表格与三种导出；含空格的文件路径。
- 损坏 Office 文件报错；已有结果目录拒绝覆盖；URL 输入拒绝。
- HTML 外部图片没有产生 HTTP 请求；文档内的字面 HTML 代码保持文本。
- 部分成功保留警告，图片子节点中的 OCR 文字在三种输出中均保留。

## 0.2 批量与生命周期回归

- 1,000 文件目录在后台扫描；重复导入不增加条目，文件修改后可以再次加入。
- 100 HTML / 20 种内容的真实 Docling 批次：第一批命中 80 份，第二批命中 100 份；缓存全命中不初始化转换器。
- 文件内容、OCR、模型身份、引擎锁与工作代码变化均使旧缓存失效；缺结果或缺 manifest 时重建；失败及部分成功不进入缓存。
- 缓存容量和过期清理保留当前引用结果；另一转换进程被缓存锁拒绝，避免双份模型争抢资源。
- 实时 stdout 事件不等待管道填满；取消清理忽略 TERM 的后代，也覆盖父进程已退出的场景。
- 批量导出同名及大小写冲突自动编号；512 KiB 预览边界不截断实际导出。
- 真实 Docling 生成的 4 MiB JSON，经复用导出后来源文件名正确，中文、引号、64 位无符号哈希不丢失，正文逐字节一致且共享缓存未修改。
- 未知 JSON 结构不覆盖已有导出；512 MiB 大文件复制进行中取消，临时文件被清理、已有目标内容保留。
- 真实 uv 修复失败时，移除旧环境就绪标记；重新启动也不会误报可用。该回归使用隔离环境，不修改实际安装环境。
- 模型下载失败、验证失败、取消时不写假状态；成功状态包含确切引擎锁和 snapshot。实际离线加载验证及 PyPI 版本检查成功。

性能样本、资源边界与测量条件见 [PERFORMANCE.md](PERFORMANCE.md)。

## 真实格式（0.1 基线与 0.2 复核）

0.1 基线每项使用脚本现场生成的文档，核对 Markdown 中确有指定中英文内容，三个导出文件非空，JSON schema 为 DoclingDocument。结果与导出哈希见 [acceptance-engine.json](acceptance-engine.json)。

| 输入 | 条件 | 结果 |
| --- | --- | --- |
| DOCX | 标题、正文、表格 | 通过 |
| PPTX | 中英文幻灯片 | 通过 |
| XLSX | 中英文表格 | 通过 |
| PNG | 中英文 Apple OCR | 通过 |
| 扫描 PDF | 图像页面，开启 OCR | 通过 |
| 扫描 PDF | 模型缓存后，HF_HUB_OFFLINE=1 | 通过，约 6.2 秒 |
| 原生 PDF | 两页中英文，关闭 OCR，HF_HUB_OFFLINE=1 | 通过，约 4.6 秒，页数为 2 |

0.2 再次用这组原生 PDF、扫描 PDF 与 PNG 完成三文件离线批次，与旧版 Markdown 逐字节一致。Office 基线输出记录沿用，未声称本轮再次逐项执行所有 Office 格式。

离线模式验收通过 Hugging Face 的离线开关完成，没有更改本机网络。原始样本、日志和逐轮回执保留在本机 `.build/acceptance-fixtures/`，可由 `scripts/verify-engine.py` 再生。首次扫描测试发现缺少 OpenCV，补入上游官方 extra 后通过。
